# Security architecture

| Surface                    | Phase 00 implementation                                                                                                                                                                                                                                                                               | Gate for the consuming module                                                                                                                                                                                                          |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Secrets and input          | Ignored environment files, empty example, Zod requires an HTTPS origin or loopback HTTP and a publishable key. Validation errors identify fields only.                                                                                                                                                | Configure real project values, secret scanning and managed rotation in deployment.                                                                                                                                                     |
| Identity and authorization | Server-only requireIdentity validates the user with Supabase. Missing/invalid sessions deny access. No application data endpoints.                                                                                                                                                                    | Add membership/role/verification/MFA and resource checks on every operation. Test each role and grant revocation with RLS.                                                                                                             |
| Cookies                    | Supabase SSR cookie adapter, SameSite=Lax, Secure in production server requests. Browser SSR flows need readable provider cookies. Dynamic responses have private no-store policy.                                                                                                                    | Refresh cookies before protected server rendering, preserve them through redirects and verify actual cache behavior in staging. Use HTTPS and allowlisted callback origins.                                                            |
| Web defenses               | Per-request nonce for Next scripts, strict-dynamic, self-hosted fonts, restricted connections, anti-framing, nosniff, referrer and permissions policies. Development allows eval for tooling. Inline styles support Radix positioning. HSTS on production HTTPS requests. React escapes preview text. | Review CSP and reverse-proxy HTTPS handling in staging. Keep external destinations allowlisted; prohibit untrusted HTML and arbitrary remote imports.                                                                                  |
| CSRF                       | Current form modifies ephemeral browser state. No server mutation routes.                                                                                                                                                                                                                             | Use Next Server Actions origin checking with exact trusted proxy origins. For cookie-authenticated custom mutations validate Origin and an anti-CSRF token where needed. Never mutate via GET.                                         |
| Errors and logging         | Client validation is associated to its field. SDK errors are reduced to a generic authentication denial. Structured security records contain fixed event, category and timestamp.                                                                                                                     | Use opaque request IDs and restricted central retention. Never record raw tokens, private conversations, identifiers from financial documents or verification evidence.                                                                |
| Dependency management      | Lockfile, strict peer checks, frozen install and pnpm audit.                                                                                                                                                                                                                                          | Reassess advisories and unsupported tooling before each release.                                                                                                                                                                       |
| Rate limiting              | Architecture only.                                                                                                                                                                                                                                                                                    | Put shared atomic limits before costly work, keyed by trusted client address, identity, tenant and action. Return 429 and Retry-After. Decide thresholds per operation and fail closed for sensitive writes if limiter is unavailable. |
| Audit                      | Architecture only.                                                                                                                                                                                                                                                                                    | Commit actor, workspace, action, object, reason, correlation ID and time transactionally with privileged changes. Restrict read access, deny application edits, evaluate tamper evidence and retention.                                |
| Uploads and isolation      | No upload routes or tenant tables.                                                                                                                                                                                                                                                                    | Implement quarantine, size/signature checks, safe rendering, scoped policies and negative tests as specified in DATABASE_ARCHITECTURE.md.                                                                                              |

Creator private growth data, drafts, earnings and AI history remain owner-scoped. Brands access only authorized professional projections or shared collaboration objects. Brand strategy and verification evidence require separate grants. Agency labels confer no client rights. Platform administrators require separate provisioning, MFA and purpose-scoped audited operations. Recovery drills, legal retention and real provider tests remain release gates.
